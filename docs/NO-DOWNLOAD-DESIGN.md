# Offline compilation: how to enable the genuine official engine

**This package intentionally has no runtime download of the PortableApps.comInstaller_*.paf.exe tool.**

## What you need

The uploaded `PortableApps_Installer_Source.zip` is a *wizard* source ZIP, not a complete generated source tree for a package. `InstallerWizard.nsi` tries to copy the installer template from `App/installer`. None of your three PortableApps source ZIPs contains that template. Hence the test can validate the guard path, but it cannot compile an official PAF from the files supplied so far.

For each app to be built using `engine: official`, supply **complete generated source** in the app's `Other/Source` folder, at minimum:

```
MyAppPortable/Other/Source/PortableApps.comInstaller.nsi
MyAppPortable/Other/Source/PortableApps.comInstallerConfig.nsh
MyAppPortable/Other/Source/... all .nsh/.bmp/ico/language support referenced by the .nsi
```

The source is normally generated by a full official PortableApps.com Installer installation (using `[Source] IncludeInstallerSource=true` in the app's `installer.ini` so generated source is retained); the app-specific generated version must be checked for current optional components, installer custom code, and compatibility. A bare wizard file or generic template cannot be compiled as the finished installer. **Do not rename `InstallerWizard.nsi` to `PortableApps.comInstaller.nsi`.**

Set `official-source-dir: ./.official-generated/MyAppPortable` if the generated sources are stored elsewhere. This uses only the `makensis.exe` compiler already installed on the Windows runner. No wizard GUI and no SourceForge / redir2 / .paf.exe download.

If a generated official template needs nonstandard NSIS plugins, install or supply the matching official plugin dependencies in the runner before compilation; the offline builder fails with the underlying compiler log rather than fetching arbitrary plugins automatically.

## Version handling

The builder reads PackageVersion, DisplayVersion, AppID and Name from the application's current `appinfo.ini` and updates only those four vendor-generated NSIS config defines **in an isolated copy**. This avoids hardcoded installer version URLs and preserves the original input. Other structural changes to app/installer.ini may require fresh generated sources. Update the vendor generated source after upstream changes, test thoroughly, and commit the verified version. Blindly auto-swapping a new template is unsafe.

## Smoke tests

- `Offline Official Source - Guard and Optional Integration Test` with empty source input: exercises custom NSIS + verifies explicit `OFFICIAL_SOURCE_MISSING`. It does **not** prove official compilation.
- Supply `official-source-dir` only when it contains complete app-matched generated official source: attempts direct compilation and dual-output validation. Failure produces no fake success claims.
